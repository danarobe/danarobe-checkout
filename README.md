# 다나로브 주문서 꾸미기 (결제슉 대체)

카페24 주문서(결제페이지)를 결제슉 없이 우리 코드로 꾸미는 프로젝트입니다.
관리 화면에서 설정을 바꾸고 **저장 후 적용**을 누르면 주문서에 반영됩니다.

## 구성

| 폴더 | 내용 |
|---|---|
| `admin/` | 관리 화면 (브라우저에서 여는 설정 페이지, 미리보기 포함) |
| `server/` | 관리 화면 서버 (`localhost:3006`) · 설정 저장 · GitHub 배포 |
| `skin/` | 카페24 스킨에 들어가는 파일: `orderform.html`(껍데기), `checkout.css`, `checkout.js` |
| `docs/` | GitHub Pages 로 공개되는 폴더. `config.js`(설정) + css/js 가 여기서 주문서로 읽힘 |
| `data/config.json` | 현재 설정. `data/history/` 에 최근 30개 저장본(되돌리기용) |
| `ANALYSIS.md` | 결제슉 조사 결과 |

## 동작 원리

1. 카페24 스킨의 `order/orderform.html` 에 아래 3줄이 들어 있습니다 (처음 한 번만 설치).
   ```html
   <link rel="stylesheet" href="https://danarobe.github.io/danarobe-checkout/checkout.css">
   <script src="https://danarobe.github.io/danarobe-checkout/config.js"></script>
   <script src="https://danarobe.github.io/danarobe-checkout/checkout.js"></script>
   ```
2. 주문서가 열리면 `config.js`(설정)를 읽어 `checkout.js` 가 로고·색·결제수단 모양·뱃지·안내문구·프로모션을 그립니다.
3. 관리 화면에서 **저장 후 적용** → `docs/config.js` 가 새로 만들어지고 GitHub 에 올라감 → 1~3분 뒤 주문서에 반영.

카페24 결제 로직(원터치 주문서 조각 `order/ec_orderform/*.html`)은 전혀 건드리지 않습니다.
카페24 Admin API 의 "디자인 파일 쓰기"는 승인된 업체만 쓸 수 있어서, 설정은 GitHub Pages 로 전달하는 방식을 택했습니다.

## 켜기

- 더블클릭: `시작.command` → 브라우저에 `http://localhost:3006` 이 열립니다.
- 또는 터미널: `cd ~/danarobe-checkout && npm start`
- 항상 켜 두기: `~/Library/LaunchAgents/com.danarobe.danarobe-checkout.plist` (설치돼 있으면 로그인 시 자동 실행)

## 처음 한 번 (설치 순서)

1. **GitHub 저장소** `danarobe/danarobe-checkout` 가 연결되어 있고 GitHub Pages(main 브랜치 `/docs`)가 켜져 있어야 합니다. → 관리 화면 "적용 상태 · 설치"에서 연결 여부 확인.
2. **테스트 스킨에 먼저 설치**: 카페24 관리자 → 디자인 → 대표 스킨 "복사"로 테스트 스킨 생성 → 스킨 편집 → `order/orderform.html` 을 관리 화면 "설치" 카드의 내용으로 교체 → 미리보기 주소에서 주문서 확인.
3. **소액 실결제 테스트** (신용카드 1건, 무통장 1건, 네이버페이 1건) 후 환불.
4. 이상 없으면 **대표 스킨**의 `order/orderform.html` 도 같은 내용으로 교체.
5. 결제슉 해지. 해지 후 결제슉이 주문서를 "원복"하므로, 원복 뒤 `order/orderform.html` 이 우리 것인지 다시 확인.

## 전환율 보강 기능 (2026-10-29)

- 무료배송 안내: 부족액이 설정값 이하일 때 "X원만 더 담으면 배송비 무료 → 장바구니", 넘기면 "무료배송 적용됨" (관리 화면 › 무료배송 안내)
- 할인코드 입력칸 접기: 평소엔 "할인코드가 있어요" 링크만, 누르면 펼침 (쿠폰·적립금 메뉴)
- 비회원 로그인 유도: 비회원 주문서 맨 위에 "네이버·카카오로 3초 만에 로그인" 박스 → 로그인 후 주문서로 복귀 (쿠폰·적립금 메뉴)
- 적립 요약: 결제금액 아래 "이번 주문으로 N원 적립 예정" (쿠폰·적립금 메뉴)
- 오늘출발 타이머: 15시 기준, 문구에 "오늘출발 상품은" 을 넣어 전 상품 오늘 출발로 오해하지 않게 함 (오늘배송 타이머 메뉴)

## 문제 생겼을 때 원복 (두 가지)

| 방법 | 걸리는 시간 | 결과 | 언제 |
|---|---|---|---|
| **A. 긴급 끄기** — 관리 화면 › 적용 상태·설치 › "주문서 꾸미기 켜짐" 끄고 **저장 후 적용** | 1~3분 (GitHub Pages 반영) | 우리 꾸미기만 꺼지고 카페24 기본 주문서 모습. 결제 정상 | 디자인·문구 문제, 급할 때 |
| **B. 스킨 파일 되돌리기** — 카페24 관리자 › 디자인 › 스킨 편집 › `order/orderform.html` 에 `backup/` 폴더의 설치 전 원본을 붙여넣고 저장 | 1분, 즉시 반영 | 설치 전(결제슉) 모습으로 완전 원복 | 결제 자체가 이상할 때, 완전 원복이 필요할 때 |

- 설치 전에 반드시 현재 `order/orderform.html` 원본을 `backup/orderform.<날짜>.html` 로 저장해 둔다.
- 결제슉은 테스트가 끝나 대표 스킨까지 확정된 뒤에 해지한다. 해지 전까지는 결제슉 파일(/shooook_/)이 스킨에 그대로 남아 있어 B 방법으로 언제든 되돌아갈 수 있다.
- 테스트 스킨(대표 스킨 복사본)에서 먼저 확인하면 운영 주문서에는 아무 영향이 없다.

## 아직 안 된 것

- **쿠폰 최대 혜택가 자동 적용**: 완성·검증됨 (2026-10-29, 다나로브 실제 주문서에서 6,000/5,000/3,000원 쿠폰 중 6,000원 자동 적용 확인). 방식: 카페24 쿠폰 창(`/coupon/coupon_select.html`)을 보이지 않는 iframe 에 띄워 카페24 자체 계산 함수로 쿠폰별 할인액을 비교한 뒤 가장 큰 조합을 카페24 "적용" 함수로 넘김. 보유 쿠폰이 있고 아직 하나도 안 썼을 때 주문서당 1회만 동작. 손님이 패널 스위치를 끄면 그 브라우저에서는 자동 적용 안 함(주소 뒤 `?dnrb_auto=off` 도 같음).
- **우리 쿠폰 선택 창**: 2026-10-29 실제 주문서에서 검증 완료(창 열기 시 기존 쿠폰 유지, 다른 쿠폰 적용, 선택 안 함, 최대 혜택 재적용, 계산용 숨은 창 정리). "사용 불가" 탭은 회원 쿠폰 목록(/myshop/coupon/coupon.html)에서 이 주문에 못 쓰는 쿠폰을 조건(구매금액·결제수단·적용상품)과 함께 보여준다. 2026-10-29 테스트 스킨에서 확인: 10만원 이상 쿠폰(350원)이 52,000원 주문에서는 "사용 불가 1 · 100,000원 이상 구매 시 사용 가능"으로, 399,000원 주문에서는 사용 가능 목록으로 옮겨지고 사용 불가 탭은 사라짐. 최대 혜택은 두 경우 모두 6,000원 유지.
- 이용약관동의 카드 (2026-10-29 운영자 요청): 비회원 주문서에서만 보인다(회원은 숨김, 단 카페24가 회원에게 [필수] 체크를 띄우면 결제가 막히지 않게 그때만 보임). "배송정보 제공방침 동의"·"청약철회방침 동의" 줄은 숨긴다(카페24에서 [필수]로 켜면 그대로 보임). "자세히"는 카페24에 등록된 약관(/order/ec_orderform/agreement/mallagree.html, personagree.html)을 페이지 안 창으로 보여준다. 비회원 실제 주문서에서 확인: 모든 약관 동의 + 쇼핑몰 이용약관 + 개인정보 수집 및 이용 2줄. 미리보기에도 회원/비회원 전환 버튼이 있고, 미리보기 "자세히"는 관리 서버가 다나로브의 실제 약관 페이지를 가져와 보여준다(/api/agreement/mallagree|personagree).
- 개인정보 수집 및 이용 동의 문구는 아직 카페24 샘플 서식 그대로("** 본 양식은 … 샘플로 제공되는 서식", "OO년", "(예시 : …)")라 운영자가 카페24 관리자에서 고쳐야 함.
- 실결제 테스트(신용카드·계좌이체·네이버페이 소액)는 아직. 운영자가 테스트 스킨 주소에서 직접 결제 후 환불.

- 적립금 줄의 "1회 구매시 적립금 최대 사용금액은 N원입니다." 는 카페24 기본 문구다(결제슉 주문서에도 똑같이 나옴). 관리자 설정은 "한도 제한 없음"이고, N 은 카페24 스크립트가 이 손님이 이번 주문에 쓸 수 있는 금액(보유 적립금)을 채워 넣은 값이라 정책 한도처럼 오해될 수 있다. → 2026-10-29 우리 주문서에서는 "현재 사용 가능한 최대 적립금은 N원입니다." 로 바꿔 보여준다(관리 화면 › 쿠폰·적립금 › 적립금 최대 사용 안내 문구, 비우면 카페24 원래 문구).

## 테스트 스킨 설치 기록 (2026-10-29)

- 테스트 스킨: **"주문서 테스트 (결제슉 대체)"** = skin15 (skin_no 20), 대표 스킨 "모이어티 반응형 - lazy-cls 테스트" 를 복사해 만듦. 대표 스킨은 손대지 않음.
- 테스트 스킨의 `order/orderform.html` 을 우리 껍데기(docs/orderform.html, 카페24 기본 v1 조각 사용)로 교체.
- 확인 주소: `https://www.danarobe.com/skin-skin15/order/basket.html` 에서 주문하면 테스트 스킨 주문서로 들어간다.
- 휴대폰도 같은 반응형 스킨을 쓴다(모바일 전용 디자인 "아키텍처"는 실제로 쓰이지 않음, 휴대폰 접속 시 www 주소에서 결제슉 주문서가 나오는 것으로 확인). 그래서 대표 스킨 한 곳만 바꾸면 PC·휴대폰 모두 적용.
- 결제슉 구조: 대표 스킨의 `order/orderform.html` 은 6줄짜리로 `/shooook_/orderform_v2.html` 레이아웃만 부른다. 원복(B)은 그 6줄(`backup/orderform.2026-10-29.shooook.html`)을 붙여넣으면 된다. `backup/` 의 html 파일은 결제슉 저작물이 섞여 있어 공개 저장소에는 올리지 않는다(.gitignore, 로컬 전용).
- 결제슉 이전 원래 주문서(`/shooook_/orderform_origin.html`)에는 운영자가 넣은 스크립트가 있었다: 토스 퀵계좌이체 자동 선택, 다른 결제수단을 고르면 "퀵계좌이체 혜택" 포기방지 팝업(1회), 예금주명 자동 입력. 결제슉 적용 중에는 이 스크립트가 꺼져 있어 지금 운영 주문서에도 없다. 우리 주문서에도 넣지 않았다.

실제 주문서에서 찾아 고친 것 (미리보기에는 없던 카페24 실제 조각 차이):
- 쿠폰이 없으면 카페24가 "0" 을 줘서 "적용 쿠폰 2장"·적립금 잠김으로 잘못 보이던 문제
- 새로고침하면 카페24가 쿠폰을 비우는데 자동 적용이 세션당 1회라 다시 안 되던 문제 → 페이지 열 때마다 1회
- 쿠폰 할인 금액이 0원으로 보이던 문제(실제 합계 칸 .mTotalCouponDiscount 사용)
- 할인코드 접기: 카페24가 나중에 줄을 숨겨서 판정이 틀리던 문제
- "최근 결제수단" 상자만 보이고 목록이 접혀 있던 문제 → 상자 숨기고 전체 목록(최근 수단이 선택된 채)
- 결제수단 글자 버튼 감싸기, 카페24 파란 선택 테두리·세로 배치 덮기, 테마색 체크박스
- 접기 화살표가 카페24 기본 화살표와 겹쳐 깨지던 문제, 적립금 줄 정리, 휴대폰 "주문/결제" 회색 띠 숨김, 채팅 버튼 숨김(결제슉과 동일)
